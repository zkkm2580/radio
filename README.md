# RadioPlayer（安卓车机收音机）

功能：
- 内置播放在线直播列表，开机自动拉取并显示条目（离线时显示上次缓存）
- 支持车机 / 方向盘上下键切换条目，确认键或点击播放
- 夜间模式跟随系统深色模式自动切换
- 点击即播（无单独播放界面），息屏持续后台播放
- 横屏 / 大按钮 / 车机适配
- 仍可手动输入流媒体 URL，或导入 M3U 播放列表

## 播放列表

启动时自动拉取并更新内置列表（HTTPS）：

    https://zj.537224.xyz/radio.txt

列表支持三种写法混排，识别后按 URL 自动去重：

```
#EXTINF:-1 group-title="电台",中国之声        ← M3U 写法（上一行是台名）
http://example.com/cnr.m3u8                  ← 纯 URL（台名自动推断）
江苏经典流行音乐广播,https://lzlive.vojs.cn/2wtSfrS/92/live.m3u8   ← 名称,URL
```

离线行为：首次拉取成功后会把原始列表缓存到本地，之后每次冷启动先渲染缓存，
让你一上车就能看到频道，再后台静默更新；拉取失败会在状态栏提示并保持旧列表。

## 播放失败时会自动做什么

车机的播放器实现差异很大，某个地址播不出来不一定是你的问题。点一个频道后，
应用会按下面顺序自动找一条能出声的线路，全程状态栏可见：

1. 原地址 + 浏览器 UA / Referer 请求头
2. 原地址裸连
3. 协议互换后的地址（https ↔ http）+ 请求头
4. 协议互换后的地址裸连

每条线路最多等 12 秒，不出声就换下一条（`prepareAsync` 在很多车机上会**无声挂起**，
既不回调成功也不回调失败，所以必须有超时看门狗）。四条都失败后，
应用会用 Python 的网络栈独立探一次源站和分片，把结论写在状态栏：

- `网络不通（...）` —— 车机联网或 DNS 有问题
- `源站正常但本机播不出声` —— 车机的解码器不支持这个编码 / HLS

一旦某条线路成功，会被记进 `good_source.txt`，下次直接走它，不再先干等一轮。

排查日志在车机的应用数据目录 `play.log`，记录每次尝试的地址与错误码。

## 常见故障速查

| 状态栏提示 | 含义 | 处理 |
| --- | --- | --- |
| `网络 IO 错误·连接被断开或源不可达` | 源站拒绝或断流 | 换台，或检查车机网络 |
| `不支持的编码` | 车机解码器不支持该音频格式 | 只能换源，应用换线路也没用 |
| 一直停在「正在缓冲」 | 播放器挂起（看门狗 12s 后会换线路） | 等它自动重试，看后续提示 |
| `源站正常但本机播不出声` | 源没问题，车机播不了 | 换一个同电台的其他镜像源 |

## 车机按键

| 按键 | 行为 |
| --- | --- |
| 上 / 下方向键、频道上下键 | 切换选中条目（到头自动循环） |
| 确认 / OK / 中控回车、播放暂停键 | 播放当前选中条目 |
| 点击条目 | 选中并立即播放 |

## 重要：明文 HTTP 说明

列表里部分电台是 `http://` 明文流（例如 `http://hg.537224.xyz:6060/...`）。
Android 9（API 28）起系统会拒绝应用的明文流量，平台的 MediaPlayer 同样会拒绝，
导致这些频道点不动。因此 `hooks/patch_manifest.py` 会在打包时
给 manifest 注入 `android:usesCleartextTraffic="true"`，不要删除这个钩子。

选中项循环与播放标记、播放候选线路生成与「记住可用线路」排序、错误码翻译。
测试用 stub 顶替 kivy 与 android，无需安装依赖。
